# Security Policy

## Scope

Security issues affecting this repository or its published artifacts should be reported privately rather than disclosed through public issues.

## Reporting

Please use GitHub's private security advisory mechanism for this repository when available.

Include:

- A clear description of the issue
- Reproduction steps or a minimal proof of concept
- Affected files, versions, or commits
- Expected and observed behavior
- Any practical mitigation already identified

Do not include secrets, private keys, credentials, or personal data in a report.

## Disclosure

Please allow reasonable time for validation, remediation, and coordinated disclosure before publishing details of a confirmed vulnerability.

## Security Baseline

Projects should treat the following as release requirements where applicable:

- No committed credentials or private keys
- Dependency and workflow review
- Deterministic tests for security-critical behavior
- Explicit trust boundaries
- Input validation and fail-closed behavior
- Reproducible builds where practical

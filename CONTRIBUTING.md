# Contributing

Contributions are welcome when they improve correctness, security, maintainability, or practical usefulness.

## Before opening a change

1. Read the repository README and any project-specific documentation.
2. Keep changes scoped to one clear purpose.
3. Add or update tests for behavioral changes.
4. Do not commit credentials, private keys, tokens, generated secrets, or personal data.
5. Prefer deterministic, reproducible changes over environment-specific behavior.

## Pull requests

A useful pull request should explain:

- What changed
- Why it changed
- How it was validated
- Any security, compatibility, performance, or operational implications

Large architectural changes should establish the constraint and evidence before introducing new infrastructure.

## Code quality

Favor clear interfaces, explicit error handling, minimal trust assumptions, and documentation that matches the implementation.
